# Release notes

GitHub Releases are the version history. Every release automatically includes merged pull requests grouped by `.github/release.yml`, author attribution, contributor information generated by GitHub, and a full comparison link.

Optionally add `docs/release-notes/vX.Y.Z.md` before pushing the tag. Its contents appear **before** the generated notes. Use it for release highlights, breaking-change details or migration steps; GitHub supplies the PR list.

For example, a release can contain:

```markdown
## Upgrade notes
Update the saved configuration before restarting DSH.

## What's Changed
### Features
* Add profile switching by @alice in https://github.com/owner/plugin/pull/12
### Fixes
* Fix saved settings by @bob in https://github.com/owner/plugin/pull/15

## New Contributors
* @bob made their first contribution in https://github.com/owner/plugin/pull/15

**Full Changelog**: https://github.com/owner/plugin/compare/v0.1.0...v0.2.0
```

The exact generated sections depend on the changes and contributors. See [the release procedure](../../playbooks/30-release.md) for PR labels and generation limits. Direct pushes can still be released; describe changes without PRs in the optional introduction when needed.

The plugin README links to GitHub Releases so npm users can read the same history. No separate `CHANGELOG.md` is maintained. Rerunning the workflow leaves an existing Release unchanged.
